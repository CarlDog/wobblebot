# 2.0.11 final 2.0.x patch and acceptance

This patch packages the counter-order notional cap repair, explicit advisor
fallbacks, native Ollama Cloud support, settings organization and archive collision
repair. The roadmap owns publication, deployment and acceptance status. Dependency
upgrades, writable POLICY and 2.1 implementation remain separate work.

The 2.0.10 tag failed its publication test gate on a missing-database reader's
worker shutdown race. This corrected patch routes all production SQLite opens
through the same guarded primitive. The earlier tag remains unchanged; no
2.0.10 release or NAS deployment was completed. The worker helper is a shared
package leaf, avoiding a service-to-concrete-adapter dependency. Read-only access,
unknown health states and cancellation behavior are preserved.

## Configuration and data compatibility

Keep the operator's current settings, prompts, provider keys and budgets. The
NAS operator file already contains the validated role-specific routes; do not
replace it with the generic example. MoE parent `fallbacks: []` entries reset the
base single-advisor chain; the populated expert/arbitrator lists hold the routes.
Ollama Cloud requires `OLLAMA_API_KEY`; provider support does not imply a selected
Ollama model. GPT-OSS 120B failed the bounded quant qualification and remains unused.

Upgrading from tagged 2.0.9 adds persisted advisor attempts and widens the LLM call
ledger's provider constraint. Existing rows, indexes and triggers are preserved;
repeat migration and injected rollback failures have regression coverage. New
Ollama Cloud rows cannot be read by old application readers. The NAS has already
run these migrations on its source-pinned image; this rollout should be idempotent.

Archive export names now include the precise UTC cutoff and a UUID. Preserve all
old and new exports. A completed export followed by a failed DELETE may leave a
duplicate recovery file on retry; that is preferable to overwriting evidence.

## Rollout and rollback

Before rollout, retain the complete current Compose document, environment in
Portainer, exact image digests and config hashes. Obtain restoration-verified online
backups. Run candidate-image validation-only preflight before restarting trading.
Stop trading/harvesting gracefully; confirm no remaining configured-symbol orders,
approved transfers or pending transfer effects before recreating them. Compare
persisted financial/approval state before and after deployment.

Use the verified tag-build image digest for every service and the tools profile,
removing the temporary maintenance-only image override. Preserve every other live
Compose setting, including service labels, mounts, health checks and credentials.

Stop acceptance for integrity/migration failures, lost alerting, approval/safety
regressions or unexpected money behavior. Retained source images `sha-1cbae64`
and maintenance `sha-4f5b32b` are the currently deployed schema-compatible rollback
baseline; record their actual digests at rollout. Do not roll back to tagged 2.0.9
with new Ollama rows. Do not overwrite post-backup trades or approvals with a stale
database snapshot. Rollback is operator-reviewed; no automated restart of live,
harvest or tools, and no diagnostic trade or transfer.

## Authorized acceptance campaign

After immediate deployment checks pass, observe for eight hours at 15-minute
intervals. Use a bounded thread heartbeat; stop at completion, failure or action
required. Remain quiet when nothing actionable changes. Check service/image/config
identity, restart/health state, public web health, advisor route/error outcomes,
maintenance/alert evidence and unrecognized safety failures. Never expose secrets,
raw commands, prompt content or financial rows in the receipt.

Natural failure/recovery and six-hour alert repetition are event-dependent. Record
missing production events as limitations, retaining the isolated test evidence;
do not manufacture an outage or wait indefinitely. Native Anthropic credit failure
is an acknowledged provider condition while Atlas failover succeeds. Failed
synthetic GPT-OSS judgments are model-selection evidence, not an application outage.

The completed observation receipt is the input to formal 2.0.x acceptance. Do not
mark the phase closed or begin N1 until its remaining limitations and closure have
been accepted. The authoritative work list remains the backlog and roadmap.
