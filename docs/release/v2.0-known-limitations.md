# 2.0.x limitations and release boundaries

These limitations accompany the 2.0.x stabilization patch; publication does not
constitute production deployment or phase acceptance. The exact version,
source/image identity, deployment and acceptance receipts belong in
[the roadmap](../planning/roadmap.md). The prior
[v1.0 limitations](v1.0-known-limitations.md) remain historical context.

| Boundary | Operator-visible consequence / next gate |
| --- | --- |
| Starvation diagnostics are snapshots | Counts and retry ticks describe the latest valid engine snapshot, not elapsed episode time. Pause/offside, current orders and stale/malformed data suppress unsupported starvation claims. |
| Older writers cannot maintain new diagnostics | A prior writer can update existing rows without understanding starvation fields. The freshness marker suppresses retained diagnostics. The local prior-image rehearsal supports this path; recheck the final tag artifact selected for deployment. |
| Corrupt pending-command row blocks its requested batch | The caller remains alive, but commands in that batch do not dispatch until explicit data repair. The sanitized row identifier is actionable; there is no quarantine, skip or approval bypass. N3 owns a broader lifecycle design. |
| Operator recovery is process supervision | Fatal required-task failures terminate the operator. Container restart policy acts on process exit; an unhealthy but still-running/wedged process does not automatically restart. N4 owns independent detection/response. |
| Delivery and command effects are not exactly once | Command claiming, crash-after-effect reconciliation, outbox durability and independent delivery remain N3. Do not infer delivery from a successful database write or healthy container. |
| Capability isolation is incomplete | ADR-041's shipped protections remain, while shared data mounts and unnecessary web cloud credentials are N1 residuals. Only Harvester has transfer authority; LLM recommendations remain advisory. |
| Build/runtime identity is not fully reproducible | Runtime dependencies use ranges, base tags can move, and CI lacks the full platform matrix. Local checks cover the declared Python floor and container runtime for this candidate. N2 owns hashed resolution, identity and recurring platform gates. |
| Historical inputs do not clear strategy gates | G1 needs usable per-signal baselines; G3 needs complete Q2 imports and canonical scoring; G4 fixes precede a paid model campaign. No outcomes, model ranking or calendar age proves dollar profit. |
| Funding/API contracts can change | The legacy Kraken withdrawal endpoint is documented as deprecated but still active. N5 must decide retention/migration and watch ownership. Public shape checks do not certify private account permissions or fund-transfer behavior. |
| Standards exceptions are scoped | E01-E03 were accepted on 2026-09-08 for this patch: current lint tools, roadmap authority and deferred CI expansion. Their owners/triggers remain in the audit packet; they do not accept deployment or phase closure. |
| Ordinary failed SQLite opens are guarded | 2.0.9 repaired the storage adapter; 2.0.11 extends the shared guard to every production open, including LLM-streak and daemon-health readers. The [roadmap receipt](../planning/roadmap.md) records verification and deployment. Earlier artifacts retain their documented concerns; initial-open cancellation retains upstream behavior. |
| Cloud alternatives are bounded and advisory | 2.0.11 packages explicit role fallbacks. Atlas equivalents may share upstream failures, and quant's primary/backup share Atlas. Native Anthropic currently lacks credit; validated Atlas failover works. Ollama Cloud transport works, but GPT-OSS 120B failed quant qualification and remains unselected. Synthetic role checks are not full seat wins; prior probe-battery limitations remain G4. |
| Cloud ledger rollback requires compatible readers | New `ollama_cloud` ledger rows cannot be read by tagged 2.0.9 application readers. The source-pinned NAS rollback baseline already understands the migration; retain its exact images and all post-backup data. See the [2.0.11 runbook](v2.0.11-upgrade.md). |
| Observation is sampled and event-dependent | The [eight-hour receipt](2.0.11-observation-evidence.json) has 33 complete checkpoints and no retrospective query gaps; health samples were up to 15 minutes 41 seconds apart. No natural task failure/recovery, stale-heartbeat repeat, high-severity delivery or another maintenance archive rotation was demonstrated. The native Anthropic credit condition persisted while Atlas failover worked; provider recovery and total-cloud-outage behavior were not exercised. Retain isolated tests and explicitly accept these production-evidence limits. |
| Deployment verification is not formal acceptance | The selected artifact, key scopes, live config, verified backups, database preservation, immediate checks and completed eight-hour observation are recorded in the roadmap. Explicit operator acceptance and phase closure remain outstanding. No diagnostic real trade or transfer was part of observation. Prior authorized advisory probe costs are recorded separately in the roadmap. |

See the [audit and decision packet](../planning/2.0-closeout-audit.md) for evidence,
rollback rules and accepted scoped exceptions, and the [backlog](../planning/backlog.md)
for owners, triggers and acceptance criteria. The sell extension remains proposed
ADR-042; neither it nor 2.1/Phase 9 is activated by this stabilization work.
