# 2.0.x limitations and release boundaries

Prepared for the final 2.0.x stabilization patch. This is a candidate limitation
register, **not release, deployment or phase acceptance**. The exact version,
source/image identity, deployment and acceptance receipts belong in
[the roadmap](../planning/roadmap.md). The prior
[v1.0 limitations](v1.0-known-limitations.md) remain historical context.

| Boundary | Operator-visible consequence / next gate |
| --- | --- |
| Starvation diagnostics are snapshots | Counts and retry ticks describe the latest valid engine snapshot, not elapsed episode time. Pause/offside, current orders and stale/malformed data suppress unsupported starvation claims. |
| Older writers cannot maintain new diagnostics | A prior writer can update existing rows without understanding starvation fields. The freshness marker suppresses retained diagnostics; real prior-image compatibility still must be rehearsed before deployment. |
| Corrupt pending-command row blocks its requested batch | The caller remains alive, but commands in that batch do not dispatch until explicit data repair. The sanitized row identifier is actionable; there is no quarantine, skip or approval bypass. N3 owns a broader lifecycle design. |
| Operator recovery is process supervision | Fatal required-task failures terminate the operator. Container restart policy acts on process exit; an unhealthy but still-running/wedged process does not automatically restart. N4 owns independent detection/response. |
| Delivery and command effects are not exactly once | Command claiming, crash-after-effect reconciliation, outbox durability and independent delivery remain N3. Do not infer delivery from a successful database write or healthy container. |
| Capability isolation is incomplete | ADR-041's shipped protections remain, while shared data mounts and unnecessary web cloud credentials are N1 residuals. Only Harvester has transfer authority; LLM recommendations remain advisory. |
| Build/runtime identity is not fully reproducible | Runtime dependencies use ranges, the verification floor differs from the container Python runtime, and CI lacks the full platform matrix. N2 owns hashed resolution, identity and platform gates. |
| Historical inputs do not clear strategy gates | G1 needs usable per-signal baselines; G3 needs complete Q2 imports and canonical scoring; G4 fixes precede a paid model campaign. No outcomes, model ranking or calendar age proves dollar profit. |
| Funding/API contracts can change | The legacy Kraken withdrawal endpoint is documented as deprecated but still active. N5 must decide retention/migration and watch ownership. Public shape checks do not certify private account permissions or fund-transfer behavior. |
| Standards exceptions are scoped | E01-E03 were accepted on 2026-09-08 for this patch: current lint tools, roadmap authority and deferred CI expansion. Their owners/triggers remain in the audit packet; they do not accept deployment or phase closure. |
| Local verification is not production acceptance | No candidate image has been selected/deployed by this audit. Key scopes, live config, prior-container migration and the finite behavior window retain their C5 checks. No real-money or paid probe was run. |

See the [audit and decision packet](../planning/2.0-closeout-audit.md) for evidence,
rollback rules and proposed exceptions, and the [backlog](../planning/backlog.md)
for owners, triggers and acceptance criteria. The sell extension remains proposed
ADR-042; neither it nor 2.1/Phase 9 is activated by this stabilization work.
